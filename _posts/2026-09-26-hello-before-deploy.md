## System Test Engineer Work

저는 자동차 제어기를 평가·검증하는 System Test Engineer로 일하고 있습니다.
이 블로그는 일하며 공부한 것, 흩어져 있던 지식, 새로 알게 된 기술을 정리해 두는 기록장입니다.

평가·검증이 중심이지만 개발도 다루고, 자동차에서 출발해 로봇까지 영역을 넓혀 갈 계획입니다.

## 무엇을 쓰나요

시스템 검증이 흘러가는 순서 — 계획하고, 설계하고, 벤치에서 수행하고, 자동화하고, 분석하고, 개선하는 과정 — 를 따라 카테고리를 나눴습니다.

| 카테고리 | 다루는 내용 |
|---|---|
| **Verification Strategy** | 요구사항 기반 검증 계획, 테스트 설계, 시스템 아키텍처 |
| **Vehicle Network** | CAN·LIN, 차량 Ethernet, 진단 |
| **Test Bench** | HIL, 시뮬레이터, 벤치 구축·운영 |
| **Test Automation** | Python, CANoe·CAPL, 장비 제어, AI를 활용한 테스트 |
| **CI-CD Infra** | 파이프라인, Linux·Git, 서버·DB, 대시보드·리포트 |
| **Result Analysis** | 로그 분석, 디버깅, 자동 결과 판정 |
| **Functional Safety** | Fault Injection, Fail-safe 검증, 표준 |
| **Development** | C·C++, Rust, 임베디드 |
| **Trends** | SDV, 자율주행, 로봇 |

## 이 블로그의 원칙

- **공개된 자료와 개인적인 공부를 바탕으로 씁니다.** 표준 문서, 공개 기술 자료, 오픈소스를 주로 다룹니다.
- **특정 회사나 제품의 정보는 다루지 않습니다.** 이 블로그의 내용은 개인의 의견이며, 어떤 조직의 공식 입장과도 무관합니다.
- **작성 방식을 제목에 밝힙니다.** 모든 글 제목에 [직접], [AI 보조], [AI 초안] 중 하나를 붙입니다.
- **틀린 내용은 고쳐 나갑니다.** 잘못된 부분이 있다면 알려 주세요.

## 엔지니어의 기록

**Engineer's Log**는 엔지니어로서 일하고 공부하며 생각한 것을 남기는 기록장입니다.
제어기는 양산 전에, 코드는 배포 전에 검증을 거치듯 — 확인하고, 근거를 남기는 엔지니어링 마인드로 쓰려고 합니다.

저는 자동차 제어기 평가·검증 업무를 하고 있습니다.
일하면서 공부한 내용, 흩어져 있던 지식, 새로 알게 된 기술을 이곳에 정리해 두려고 합니다.

## 무엇을 쓰나요

평가·검증이 중심이지만, 개발과 인접 분야까지 넓게 다룹니다.

| 카테고리 | 다루는 내용 |
|---|---|
| **Trends** | SDV, 자율주행, E/E 아키텍처, 표준·규제 동향 |
| **Validation** | 테스트 방법론(MIL/SIL/HIL), 진단(UDS), 차량 네트워크, 기능안전 |
| **Toolchain** | Vector, dSPACE, 오픈소스 테스트 도구 |
| **DevOps** | CI/CD/CT 파이프라인, 테스트 자동화, 테스트에 AI 활용하기 |
| **Development** | 임베디드 SW, AUTOSAR, Python·CAPL 스크립팅 |
| **Robotics** | ROS, 로봇 제어기 검증 |

자동차에서 출발했지만, 제어기를 검증한다는 본질은 로봇에서도 같다고 생각합니다.
그래서 로봇 분야까지 조금씩 영역을 넓혀 갈 계획입니다.

## 이 블로그의 원칙

- **공개된 자료와 개인적인 공부를 바탕으로 씁니다.** 표준 문서, 공개 기술 자료, 오픈소스를 주로 다룹니다.
- **특정 회사나 제품의 정보는 다루지 않습니다.** 이 블로그의 내용은 개인의 의견이며, 어떤 조직의 공식 입장과도 무관합니다.
- **틀린 내용은 고쳐 나갑니다.** 잘못된 부분이 있다면 알려 주세요.

검증하는 사람의 시선으로, 배포 전에 한 번 더 확인하는 마음으로 기록하겠습니다.
